The problem

You can't secure what you can't see.

Web applications and APIs accumulate surface that conventional inventories miss. The hard part isn't finding signals, it's understanding how they relate.

  • Undocumented endpoints
  • Parameters that only appear after JavaScript runs
  • Broken access control and IDOR
  • Components with known CVEs
  • Insecure headers and configuration
  • Exposed sensitive data

Traditional scanners return a volume of alerts without enough context to act on.

TRACE turns that noise into structured, correlated and prioritized information, keeping the technical evidence behind every conclusion.

Method

How it works

An expert-led assessment, from initial mapping to the final report.

  1. 01

    Step 01: Discover

    Maps endpoints, parameters and the application surface, including SPAs, through real JavaScript rendering.

  2. 02

    Step 02: Profile

    Collects information on the technologies, versions and behavior of discovered assets.

  3. 03

    Step 03: Analyze

    Correlates facts in the decision engine and identifies real attack paths and exposure.

  4. 04

    Step 04: Explain

    Turns raw data into the causal chain behind each finding and a prioritized report.

Capabilities

Features

Real technical coverage to discover, correlate and communicate risk in web applications and REST APIs.

Web & API reconnaissance

Enumeration of web applications and REST APIs, with a Chromium/Playwright crawler that renders real JavaScript to cover SPAs.

Fact-engine correlation

Modules only run once the facts they depend on are established. The decision graph records why every test ran.

OWASP Top 10 coverage

BAC/IDOR, injection (SQLi, XSS, SSTI, command injection, LDAP), SSRF, cryptographic failures, outdated components, misconfiguration and JWT.

Vulnerability intelligence

Identified versions of servers, libraries and plugins are matched against the NVD and Wordfence Intelligence feeds.

Severity-based prioritization

Critical findings come first, along with each finding's lifecycle: new in this assessment or persistent across assessments.

Client report

PDF with OWASP/CWE taxonomy, technical evidence, an audit trail and optional mapping to LGPD, Brazil's data protection law. Not legal advice.

Specialized module

WordPress

Detects plugins and themes, identifies their versions and matches them against known vulnerabilities from the Wordfence Intelligence feed.

Why TRACE

From raw discovery to security intelligence.

Traditional tools return large volumes of data. The real challenge is understanding what that data means.

TRACE works as a discovery, correlation and explanation layer, not just another scanner. The decision graph connects facts and preserves the causal chain: payload, URL, evidence and suggested command. The result shows how each finding was reached and why it deserves priority.

Traditional scanner

  • Runs every test against everything
  • Treats a status code as proof
  • Flat list of alerts
  • Every run starts from zero

TRACE

  • Activates modules based on discovered facts
  • Confirms the effect, not just the response
  • Explained causal chain for every finding
  • Memory across assessments: new, persistent, fixed

FAQ

Frequently asked questions

What is TRACE?

TRACE stands for Transparent Reconnaissance & Attack Correlation Engine. It is a reconnaissance and attack correlation engine for web applications and REST APIs, delivered as an expert-led security assessment.

What does TRACE do?

TRACE discovers endpoints and parameters, profiles technologies and versions, detects vulnerabilities across the OWASP Top 10 taxonomy, correlates evidence and explains the causal chain behind each finding in a report ranked by severity.

Who is TRACE for?

Pentesters, red teams, security engineers, SOC teams, threat hunters, consultants and internal security teams who need to understand the attack surface of web applications and APIs.

What environments can TRACE analyze?

Web applications and REST APIs, including JavaScript-heavy SPAs and WordPress sites. TRACE does not perform host or port discovery on internal networks.

Is TRACE a vulnerability scanner?

It detects vulnerabilities, but its focus is different: relating facts, explaining evidence and prioritizing what matters, instead of returning a long list of isolated alerts.

How is TRACE different from traditional scanners?

Traditional scanners usually run every test against everything and report alerts without context. TRACE decides what to test based on what it has already learned about the target, records the reason for each decision in a graph and shows, for every finding, the path of payload, URL and evidence that led to it.

Can TRACE be used in authorized security assessments?

Yes, and only in those. Every assessment is expert-led and requires formal authorization from the owner of the environment. Intrusive tests require explicit confirmation, and artifacts created during testing are logged and removed at the end.

Can TRACE support red team work?

Yes, during the reconnaissance phase for web applications and APIs: the decision graph shows which chained facts led to each exposure, which helps plan attack paths. TRACE does not cover internal network infrastructure, Active Directory or social engineering.

Can internal security teams use TRACE?

Yes. Internal teams use the report to prioritize fixes, track new and persistent findings across assessments and keep a technical audit trail.

Is TRACE available?

TRACE is in active development and has been validated against intentionally vulnerable reference targets such as VAmPI and DVWA. Join the early access list for updates, technical releases and invitations when assessment slots open.

In short

TRACE is a reconnaissance and attack correlation engine for web applications and REST APIs, delivered as an expert-led security assessment.

It renders SPAs, covers the OWASP Top 10 taxonomy, matches components against the NVD and Wordfence Intelligence feeds and explains every finding through a fact engine and a decision graph. Reports are ranked by severity, keep an audit trail and track each finding's lifecycle across assessments.
